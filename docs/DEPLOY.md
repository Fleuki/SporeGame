# ПУБЛИКАЦИЯ

Игра лежит в `docs/` и раздаётся GitHub Pages как есть: ни сборки, ни
зависимостей, ни шага компиляции. Настройка одна — в репозитории
**Settings → Pages** источником стоит ветка `main`, папка `/docs`.

## Почему рядом лежит пустой `.nojekyll`

Pages по умолчанию прогоняет сайт через Jekyll — генератор блогов. Этому
проекту он не нужен ничем: здесь нет ни шаблонов, ни постов, ни front-matter,
только готовые html/js/css/png. Зато Jekyll умеет молча ломать сборку и
глотать файлы — например, всё, что начинается с подчёркивания.

Пустой файл `.nojekyll` выключает его целиком: Pages просто копирует папку.
Сборка становится быстрее и предсказуемее, а класс ошибок «на диске файл есть,
на сайте 404» исчезает.

## Если на сайте старая версия

Так уже было: PR влит, файлы в `main` лежат, а `fleuki.github.io/SporeGame`
отдаёт вчерашнюю сборку.

Проверять по порядку, каждый шаг отвечает на свой вопрос:

1. **Файл вообще в ветке?**
   `git cat-file -s $(git rev-parse origin/main:docs/assets/images/ui/screen_death.png)`
   Ошибка — значит дело не в деплое, файл не доехал.

2. **Что реально отдаёт сайт?** Смотреть не глазами, а заголовком:

   ```
   curl -sSI https://fleuki.github.io/SporeGame/css/style.css | grep -i last-modified
   ```

   Дата раньше последнего мерджа — сборки не было. Дата свежая, а изменений
   не видно — значит кеш браузера, и лечится жёстким обновлением
   (Ctrl+Shift+R, на телефоне — очистить данные сайта).

3. **Сборка запускалась?** Вкладка **Actions** в репозитории, задача
   «pages build and deployment». Она появляется даже без своего workflow.
   Красная — открыть лог; её же можно перезапустить кнопкой «Re-run jobs».

4. **Ничего не помогло** — любой новый коммит в `main` заново запускает
   деплой. Этот файл в том числе для этого и годится.

Между мерджем и обновлением сайта обычно проходит одна-две минуты. Больше
десяти — уже не задержка, смотреть Actions.
