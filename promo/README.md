# ПРОМОМАТЕРИАЛЫ ДЛЯ КАРТОЧКИ ИГРЫ

Эта папка **не уезжает в игру**. Всё, что лежит в `docs/`, копируется в архив
для площадки целиком (`tools/build_yandex.mjs`), и восемь полноэкранных PNG
утяжелили бы игру на семь мегабайт ради картинок, которые игроку не нужны.
Поэтому промо живёт здесь, рядом с проектом, а не внутри него.

## screenshots/

Снимаются одной командой, а не рукой:

```
node tools/shots.mjs           # вся подборка
node tools/shots.mjs boss      # только кадры, чьё имя содержит подстроку
```

Playwright в зависимости проекта не входит (игра остаётся папкой без сборки) —
ставится тому, кто снимает: `npm i -g playwright && npx playwright install chromium`.
Готовые снимки лежат в репозитории, так что ради самих картинок скрипт
запускать не надо: только когда игра изменилась.

| файл | что на нём |
|---|---|
| `01-boi` | обычный бой, полторы минуты забега |
| `02-boss` | Материнская Капля, полоса здоровья и выводок |
| `03-prokachka` | меню прокачки: три карточки из разных веток |
| `04-lavka` | прилавок с четырьмя товарами и перерисовкой |
| `05-vybros` | выброс спор в момент удара, взятый уровень |
| `06-08` | то же самое в портретной ориентации, для телефонов |

**Размеры выбраны под вёрстку, а не под красивые числа**: 1280x720 и 900x1600
в окне браузера — единственные, при которых коробка игры совпадает с кадром.
В 1920x1080 игра рисуется окном посередине страницы, и треть снимка занимает
пустой фон — на площадке это провал сразу по двум пунктам требований
(«геймплей не меньше 70% кадра» и «сплошная заливка вместо содержания»).
Итоговое разрешение добирается плотностью пикселя: 1920x1080 и 1080x1920.

Рамку холста скрипт снимает намеренно: в игре это часть оформления, а в
карточке магазина рамки запрещены прямым пунктом требований к медиаматериалам.

## video/

Горизонтальное промо-видео для карточки. Снимается тем же способом и по той же
причине, что и скриншоты:

```
node tools/video.mjs          # promo/video/gorizontalnoe-16x9.mp4
node tools/video.mjs --keep   # оставить исходный webm рядом
```

Нужен ещё ffmpeg — берётся из PATH, из переменной `FFMPEG` или из пакета
`ffmpeg-static` (`npm i -g ffmpeg-static`).

| что требует консоль | что отдаёт скрипт |
|---|---|
| mp4, 16:9 | mp4 H.264, 1280x720 |
| высота от 400 пикселей | 720 |
| не длиннее 28 секунд | 26.0 |
| не больше 100 МБ | около 3.5 МБ |

Сценарий (26 секунд) собран из шести сцен: название на стартовом экране, бой
на четвёртой минуте, меню прокачки, лавка, выброс спор и бой с Материнской
Каплей. Между сценами — прямая склейка: перемотка забега и ожидание босса в
ролик не попадают.

**Название в первых кадрах — не украшение.** П. 5.1.3 требует, чтобы название
в видео совпадало с названием в карточке побуквенно, и показать его негде,
кроме стартового экрана.

Три решения, которые легко отменить по незнанию (все — из прогонов, каждое
чинило испорченный ролик):

- **Размер видео равен размеру окна.** Playwright умеет уменьшать страницу под
  заданный размер, но не увеличивать: при окне 1280x720 и видео 1920x1080 он
  кладёт игру в угол кадра и оставляет треть пустой.
- **Плотность пикселя — единица.** При 1.5 холст рисуется вдвое крупнее и
  ужимается до размера видео, а пересчёт пиксель-арта — это мыло, то есть
  запрещённые п. 8.3.1 «пиксельные артефакты».
- **Бота надо держать живым в КАЖДОМ ожидании.** Пока Playwright ждёт своё
  условие, бот не подновляет себе здоровье — забег кончается за секунды, и
  босс, которого ждали, не выходит уже никогда.

Босс снимается на ПЕРВОМ (2:45), а не на втором: пока босс жив, рядовые враги
не спавнятся, и на пятой минуте он выходит в уже выкошенную арену — кадр
получается тёмным и пустым.

## Чего здесь НЕТ и почему

**Иконки и обложки.** Скриншот в качестве иконки или обложки площадка
запрещает, поэтому они рисуются отдельно — промпты лежат в
`docs/ASSET_PROMPTS.md`, раздел «Промоматериалы для площадки».
